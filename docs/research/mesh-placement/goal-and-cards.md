# Workload placement: goal and cards

Source ADRs: `docs/adr/adr-099-governed-workload-placement.md`, `adr-100-cog-workload-kind.md`, `adr-101-inference-workload-kind.md` (all Proposed; open questions settled 2026-09-29, defaults accepted by user, so their decisions are settled pending implementation). Card format mirrors `node scripts/dashboard-board.mjs create <stable-source-key> <title> <description> [source URL]` (`scripts/dashboard-board.mjs:17,109-117`; description must be at least 20 characters). Below, each card gives key, title and description; the description embeds dependencies, acceptance criteria, an observable completion condition and the ADR citation. Nothing has been created on the board. Settled decisions embedded in the cards: pinned WeftOS signer set plus operator-pinned keys (Cognitum records optional); operator attestation over hash manifests for models; our cogs fork is the source of truth; Cognitum's 30% is contractual only; WASM unifies on `clawft-wasm-host`; emulation is operator opt-in only; new `workload.*` RPC family; loopback proxy for inference clients; `~/llm` stays a separate repo; `0.0.0.0` bindings only with auth via a chained Permit; vocabulary changes go through governance; no weight-transfer ceiling in v1; Seed v1 adapter is its own API (option b). Key prefix is `mesh-placement-` (renamed from `cogs-mesh-` when scope widened).

## Goals

**Goal A (first vertical slice, cogs).** Hardware validation so far (2026-09-29): a Pi 5 running weaver v0.8.1 as a mesh member runs released aarch64 cogs natively (anomaly-detect, fall-detect, baby-cry, sleep-apnea ingest), and a Cognitum Seed was driven through its own HTTP API; the placement layer itself is unbuilt. Cogs run under WeftOS governance as loadable workloads placed onto the correct mesh node. Completion: from the Mac, `weaver workload place cog:anomaly-detect` selects a paired real ARM node (Pi 5 through the native adapter, or a Seed through the Seed API adapter) over the Mac; the node (Pi 5 case) fetches the signed package over the mesh, verifies hash and pinned-signer signature, and runs the aarch64 binary natively on the sensor's LAN under the native adapter; (Seed case) the adapter installs the pinned store cog through the Seed API; vectors land in the WeftOS store. With that node unpaired, the same command places the cog in an OrbStack or Apple `container` container on the Mac and vectors still land. Every place/install/load/start/unload/refusal is an ExoChain event. An unsigned package and a revoked package are refused (chained); revoking a running package unloads it everywhere. The conformance tool passes on both adapters. `weaver workload place --explain` shows candidates, scores and failed constraints.

**Goal B (general layer and accelerators).** Nodes advertise an open accelerator vocabulary (Metal GPU and ANE on this Mac first); placement matches requirements to capabilities for any workload kind. Completion: `weaver cluster nodes --facts` shows the Mac's probed capabilities (`accel.gpu.metal`, `mem.unified`, runtimes, ANE marked with its provenance); a synthetic workload requiring `accel.tpu.coral` or an `x.` id is reported `Unplaceable` with the reason, and after a test node advertises that id it is placed, with no kernel code change.

**Goal C (local inference on the layer).** An inference endpoint is a placed workload with a stable mesh address, and the provider router resolves it through the placement layer. Completion: the Hermes role and Orpheus TTS on this Mac run as `Managed` inference workloads; `local/` and `ollama/` model strings resolve via placement (constants remain only as fallback); moving the workload to a second node keeps `http://127.0.0.1:8090` working through the proxy; all placements chained.

- Deps: none

### mesh-placement-02: Open capability vocabulary and accelerator record types
- Description: Add the `Capability`/`Requirement` types (dotted id, attrs, provenance claimed/probed/measured, state available/busy/reserved/degraded, exclusive), matching by exact id or prefix with attr predicates (eq/gte/lte/in/has), a `config/capabilities.toml` well-known vocabulary (cpu/os/runtime/accel gpu-npu-tpu-tsu-other/format/mem/feed/store/trust) used for validation warnings only, and the `mem.unified` shared-pool rule. Unknown ids are accepted and matched. Changes to the vocabulary file go through the governance path, not free edits. Includes measured-performance capabilities (`perf.cog.cycle_ms{cog_id}`, `perf.infer.tok_s{model}`) with provenance `measured`. No hardware code. Depends on: 01. Acceptance: unit tests for matching, unknown ids, `x.` ids, unified-memory accounting, serde round-trip; a requirement naming an unseen id matches only a node advertising it. Completion: `cargo`-free check via `scripts/build.sh test` green and a doc table generated from the vocabulary file. Source: ADR-099 section 2; ~/llm docs/adr/0004-open-capability-vocabulary.md.
- Deps: 01

### mesh-placement-03: Node facts probe and signed advertisement (Mac first)
- Description: `node_facts` module probing arch/os, runtimes (docker/OrbStack variant, Apple container, podman, native, llama-server, mlx_lm, ollama), emulation (binfmt/qemu), memory, storage tiers (drive mounted), sensor feeds, and accelerators (Metal GPU via system_profiler/sysctl, ANE presence via chip+CoreML with honest provenance, others only if a tool is present). Probe results carry provenance, and measured `perf.*` values are populated by the conformance harness and admission probes (motivation: a Pi Zero 2 W cycle at `--interval 1` takes about 6 s versus about 1 s on a Pi 5, both passing every hard constraint). Sign with the node key beside `SignedCapabilityAdvertisement` (`capability_claim.rs:109`), TTL cache in `ClusterMembership`, small busy/free delta messages. Depends on: 02. Acceptance: on this Mac facts show aarch64, macos, unified memory 128 GB, Metal GPU, docker=orbstack native aarch64 + emulated armv7, apple-container aarch64; tampered/expired facts rejected; mocked-probe tests for Linux ARM and a fake Coral. Completion: `weaver cluster nodes --facts` prints Mac facts with provenance. Source: ADR-099 section 2; cluster.rs:87-117; capability_claim.rs.
- Deps: 02

### mesh-placement-04: Workload spec and pure placement engine
- Description: `WorkloadSpec { kind, requirements, policy }` and a pure `place(request, facts[], cluster_state) -> Decision` with hard constraints (requirements, trust, provenance, liveness, revocation, co-residency `excludes`, gate) then scoring (native over emulated over dev-mac; locality; accelerator fit; measured performance, with a cycle-time budget filter for interactive workloads; load; stickiness), pins/affinity, explicit operator-opt-in emulated fallback (never automatic), `Unplaceable` with per-node reasons, and an explain output. Depends on: 02. Acceptance: table-driven tests over synthetic Mac, Pi 5, Seed, x86, GPU box, fake Coral/TSU nodes; pin to ineligible node errors naming the constraint; emulation only with flag; no kind-specific code in the engine. Completion: test suite green; `--explain` snapshot tests. Source: ADR-099 section 3.
- Deps: 02

### mesh-placement-09: Runtime adapter trait, native, container and Seed API adapters
- Description: `WorkloadRuntime` trait (id, provides, admit, load, start, stop, unload, status, control_mode) with native-process (unprivileged, `[console]` limits, rlimits, RunEvidence) and container adapters (apple-container, docker/OrbStack, podman) building a minimal image from the verified artifact, replacing the simulated start at `container.rs:383-405` for workloads; host-contract wiring for cogs (`COG_CSI_BIND`, `COG_SENSOR_URL`, token, data dir). **Also folds in the Seed API runtime adapter** (`remote.api`, ADR-100 section 5; no separate card): it drives a Cognitum Seed's own HTTP API (`/api/v1/apps/install`, `/apps/{id}/start|stop|console|logs|config|manifest`, pairing via `/api/v1/pair/window` and `/pair`), honors the Seed constraints (concurrency cap 3, stop running instances before a console run because of UDP 5006 contention, installed cogs auto-start, store registry lacks anomaly-detect so v1 Seed cogs are fall-detect or baby-cry), keeps the per-Seed credential in the operator secret store (never in chain events), treats firmware upgrade as a governed backed-up operation (a 0.10.x upgrade hit the witness-chain `writes_gated` state, recovered with `/api/v1/store/truncate-confirm` after a backup), and installs only store packages the operator pinned by id and version. WASM adapters, when built, use `clawft-wasm-host` (the kernel `wasm_runner` is retired or wrapped for cogs). Depends on: 05, 07, 08, 02. Acceptance: anomaly-detect runs under each adapter available on the Mac and under native on Linux ARM (the Pi 5 already runs released aarch64 cogs natively); fall-detect installs, starts, runs one console cycle and stops on a real Seed through the Seed adapter; limits enforced; harness green per adapter; each adapter `provides()` its capability ids. Completion: harness passes for native (Linux ARM or aarch64 container standing in), apple-container and docker. Source: ADR-099 section 5; ADR-100 sections 3-4; supervisor.rs:298-322.
- Deps: 02, 05, 07, 08
