## ADR-103 Phase 4 review

**The Linux container blocker is a real contract mismatch, not an unresolved ADR decision.** D9 already selects containers as a project sandbox and keeps the project kernel inside the workload, supervised from outside. D10 already makes nested WeftOS isolated by default and gives `weave.master = true` authority to manage registration under that master. D8 requires every nested policy to tighten its parent’s rules. [ADR-103](<~/.codex/worktrees/topology-finish/weftos/docs/adr/adr-103-weave-topology-roles-and-instances.md:42>)

### Failing cases in the current path

- A container’s kernel PID is in its own PID namespace. The parent’s `note_pid`, readiness comparison, session re-registration and adoption checks compare it with a **host** PID. A healthy container can therefore fail registration or readiness; a restarted daemon cannot adopt it through `kernel.pid`, host executable name and `flock`. [child.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/project_supervisor/child.rs:503>), [adopt.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/project_supervisor/adopt.rs:186>), [mesh_local_rpc.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/mesh_local_rpc.rs:146>)
- `spawn.json` carries a host parent socket and root path; bootstrap registers its in-container socket path. Those paths need explicit host and guest meanings. The child also needs a writable runtime for its socket, PID and lock, while `user.pub`, `parent-policy.json` and `revoked` must remain outside its write authority. Mounting the current whole run directory writable breaks that trust assumption. [spawn.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-types/src/project/spawn.rs:39>), [project_boot.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/project_boot.rs:285>), [runtime_paths/child.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-types/src/runtime_paths/child.rs:128>)
- The existing cog container adapter supplies useful engine command, inspect and isolation patterns, but its in-memory instance table and cog-specific image/build path cannot provide project adoption after daemon restart. [container.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-kernel/src/workload_runtime/container.rs:94>), [container_cmd.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-kernel/src/workload_runtime/container_cmd.rs:167>)

### Minimal implementation contract

1. **Represent runtime identity explicitly.** In [logical.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-kernel/src/workload_runtime/logical.rs:33>), replace PID-only `ChildRef`/`ChildProbe::Running` identity with `Native { host_pid } | Container { engine, immutable_container_id }`; keep the existing native behavior. Add the same tagged identity to supervisor [state.json](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/project_supervisor/state.rs:12>) and status. A guest PID is diagnostic only. The supervisor’s `wait_ready` must match the certified project and the **inspected container ID**, through the registration expectation; it must not equate guest PID with host PID.

2. **Add a project container launcher behind the existing supervisor gate.** Extend [ProjectSandbox](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-types/src/project/schema.rs:137>) with an explicit Linux container driver. In [child.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/project_supervisor/child.rs:472>), dispatch native/Seatbelt versus a new project-specific container launcher; keep `Supervisor::prepare`, `WorkloadHost`, restart budget, token revocation and chain transitions in [mod.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/project_supervisor/mod.rs:183>). Reuse the engine command runner and inspect parser from the cog adapter, not its cog `WorkloadRuntime` instance map. Use an operator-pinned image, deterministic name plus **engine-returned immutable ID**, and fail closed on unsupported engine flags. Limit capabilities, privilege escalation, processes and mounts.

3. **Separate host and guest paths.** Add a container transport/path section to `SpawnFile`: guest parent UDS, guest runtime root, guest project root, and the host-reachable child UDS; retain legacy fields for native launches. Mount only the project’s required durable state writable and a dedicated child runtime writable. Bind the parent UDS at a fixed guest path with access to that socket only. Present `spawn.json`, `user.pub`, signed policy and revocation state through parent-controlled read-only mounts (or an equivalent parent-controlled channel); never make their containing host directory writable to the container. Update [project_boot.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/project_boot.rs:180>) and [project_boot_link.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/project_boot_link.rs:64>) to use the guest endpoint while preserving the user-key signature, pin, certificate, policy and nonce checks. Configure ownership/UID mapping so the guest can read the private bootstrap material without granting it host run-root writes.

4. **Bind registration to the container, not its PID claim.** Extend `SpawnExpectation`, `RegisterRequest` and the project-key binding signature with container identity and host-reachable socket, versioning the signed layout. The parent must compare the submitted container ID to an engine inspect result and its outstanding nonce **after launch**, before accepting a session. Store that identity in `NewSession`; re-registration and heartbeat must remain tied to it. Do not accept `pid = 0`, the guest PID, a container name, or a caller-supplied host socket as proof by itself. [mesh_local_registry.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/mesh_local_registry.rs:37>), [mesh_local_rpc.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/mesh_local_rpc.rs:165>), [mesh_local.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-rpc/src/mesh_local.rs:162>)

5. **Stop and adopt by inspected engine identity.** In [adopt.rs](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/project_supervisor/adopt.rs:186>) add a container scan alongside native PID scanning. Adopt only when the persisted immutable ID exists, engine labels identify this project and supervisor, its configured mounts match, and a signed/verified child handshake answers through the host endpoint. On uncertainty, report an unverifiable leftover and neither start a duplicate nor remove it. Graceful signed `kernel.shutdown` goes first; then engine `stop`, then force removal, with the immutable ID re-inspected before **each** destructive call. Restart uses the existing budget and creates a fresh container ID.

6. **Make nested registration an explicit master action.** The current [nested check](<~/.codex/worktrees/topology-finish/weftos/crates/clawft-weave/src/project_supervisor/mod.rs:244>) validates a declared parent’s active manifest, canonical root containment and `weave.master`; it does not register an inner WeftOS instance. Add a narrow `project.nested.register` parent RPC authenticated to the master project identity (or its project-scoped token with a dedicated method grant). It must verify `weave.master`, parent ID, canonical containment where roots are shared, a distinct certified inner identity, permitted registration level, and a policy no looser than the master’s effective policy. Record the parent link and cap; expose no automatic outer-mesh join. Ordinary `project.register` remains owner/Admin scoped. A nested instance starts with its isolated `WEFTOS_RUNTIME_DIR` and joins the outer mesh only through this accepted registration.

**Proof cases for the lane:** guest PID differs from host PID yet starts; forged container ID or socket is refused; writable runtime cannot replace the pin/policy; daemon restart adopts the same inspected ID; stale ID is never stopped; failed inspection blocks duplicate launch; revoked container is stopped without respawn; a non-master or looser nested registration is refused.
