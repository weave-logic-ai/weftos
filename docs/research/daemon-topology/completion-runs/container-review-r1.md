1. **Writable project mount can expose parent trust files.** [container_mounts](/Users/mathewbeane/.codex/worktrees/project-container/weftos/crates/clawft-weave/src/project_supervisor/child.rs:575) mounts the project root read/write and `<run>/<id>` read-only as trust. With `WEFTOS_RUNTIME_DIR` inside the project, the guest can write `user.pub`, policy, spawn, or state files through `/weftos/project` despite the read-only trust mount. A container with an extra writable bind or a network attached after creation still passes adoption and stop verification. Compare the complete mount set and required isolation fields; add rejection fixtures.

An unavailable engine or failed identity check must produce an unverifiable/error state, never a verified running result.

If create succeeds but inspect or state persistence fails, the deterministic name remains occupied with no saved ID for safe removal or adoption. Persist the returned ID immediately, then inspect, or retain it for verified cleanup.
