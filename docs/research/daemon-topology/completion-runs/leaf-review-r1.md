## Leaf lane review

**Blockers to claiming a working signed, offline observation path**

1. **The IDF firmware produces no observations.** `touch_loop` reads and logs touch points but has no channel to `LeafLink`; `mesh::run` only journals and signs `mesh.subscribe`. The host WLF1 path is implemented, but the device never sends a signed input publish. Connect touch events to an enqueue path that commits NVS before transmission. [IDF main](</Users/mathewbeane/.codex/worktrees/leaf-finish/weftos/crates/clawft-edge-pad-idf/src/main.rs:198>), [IDF mesh](</Users/mathewbeane/.codex/worktrees/leaf-finish/weftos/crates/clawft-edge-pad-idf/src/mesh.rs:114>)

2. **Pending observations can prevent subscription after reboot.** `subscribe_if_needed` skips subscribe whenever the queue is nonempty. Once an input producer exists, a reboot with a pending input frame replays it, then enters the display receive loop without registering the push topic. Keep connection-local subscription separate from the durable observation queue, or enqueue/replay a subscribe for each new connection. [IDF mesh](</Users/mathewbeane/.codex/worktrees/leaf-finish/weftos/crates/clawft-edge-pad-idf/src/mesh.rs:114>)

3. **The replay reader assumes the next frame is an ACK.** The server can send queued display pushes and signed ACKs on the same connection. During later publishes, a push may precede an ACK; both the IDF and CLI replay readers then reject the push as an “unsigned ACK” and reconnect. Demultiplex complete length-prefixed frames while waiting for the ACK matching the oldest journal entry. The server’s ACK itself is correctly sent as a full `WLA1` frame. [IDF mesh](</Users/mathewbeane/.codex/worktrees/leaf-finish/weftos/crates/clawft-edge-pad-idf/src/mesh.rs:155>), [CLI](</Users/mathewbeane/.codex/worktrees/leaf-finish/weftos/crates/clawft-weave/src/commands/leaf_cmd.rs:436>), [pump](</Users/mathewbeane/.codex/worktrees/leaf-finish/weftos/crates/clawft-kernel/src/mesh_serve.rs:520>)

4. **An advertised capability has no receive path.** The wire type accepts `substrate.publish`, and provisioning accepts arbitrary capability strings, but `leaf_routed_envelope` only routes input, announce and subscribe. A provisioned leaf can durably queue a valid `substrate/<leaf-id>/...` frame that the parent will always refuse, blocking subsequent ordered replay. Either implement its scoped substrate bridge or reject that capability/target at provisioning and enqueue. [link.rs](</Users/mathewbeane/.codex/worktrees/leaf-finish/weftos/crates/weftos-leaf-types/src/link.rs:192>), [mesh_serve.rs](</Users/mathewbeane/.codex/worktrees/leaf-finish/weftos/crates/clawft-kernel/src/mesh_serve.rs:307>)

**Verified contract in source:** WLF1 frames bind leaf key, certificate, parent scope, sequence, target and payload; enrollment and the persisted replay floor are checked before delivery. The service stamps the certified scope and refuses a missing parent tenant, and a full machine-signed ACK follows successful handoff and floor commit. A crash between handoff and floor commit can redeliver once: this is the documented **at-least-once** window, not an exactly-once guarantee. [link.rs](</Users/mathewbeane/.codex/worktrees/leaf-finish/weftos/crates/weftos-leaf-types/src/link.rs:164>), [mesh_leaf.rs](</Users/mathewbeane/.codex/worktrees/leaf-finish/weftos/crates/clawft-kernel/src/mesh_leaf.rs:168>), [router.rs](</Users/mathewbeane/.codex/worktrees/leaf-finish/weftos/crates/clawft-mesh-service/src/router.rs:393>)
