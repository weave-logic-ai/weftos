# [66] π³: Scalable Permutation-Equivariant Visual Geometry Learning

**Citation:** Wang et al. (2025c). Y. Wang, J. Zhou, H. Zhu, W. Chang, Y. Zhou, Z. Li, J. Chen, J. Pang, C. Shen, T. He. "Pi3: scalable permutation-equivariant visual geometry learning." arXiv e-prints, pp. arXiv–2507. (Later: ICLR 2026)
**URL:** https://arxiv.org/abs/2507.13347 (code: https://github.com/yyfz/Pi3)

## Summary
π³ (Pi3) is a feed-forward multi-view geometry network that predicts camera poses and point maps directly from a set of unordered images, without a reference/anchor frame — a fully permutation-equivariant architecture, unlike prior methods (e.g. VGGT, DUSt3R-family) that pick a reference view and break down under reordering. It reports SOTA on camera pose estimation, monocular/video depth, and dense point-map reconstruction, and scales more robustly with input-set permutation than earlier feed-forward multi-view models.

## Architecture / I/O
Input: an unordered set of RGB images (no poses/intrinsics required). Output: affine-invariant camera poses + scale-invariant local point maps per image, i.e. **relative geometry only, up to a similarity transform**, by design — the base π³ model does not claim metric scale. The successor variant **Pi3X** adds a convolutional head and *optional* conditioning on camera poses/intrinsics/depth, which enables **metric-scale reconstruction only when such an external anchor is supplied**; without it, Pi3X still outputs scale-ambiguous geometry. For WeftOS: neither variant is metric out of the box — any absolute scale must come from an external sensor or known reference object, not from Pi3 alone.

## Sizes / Variants
Two named releases: **Pi3** (original, scale-invariant only) and **Pi3X** (adds convolutional head, optional metric conditioning, smoother output, improved confidence scoring). No small/base/large parameter tiers documented in the README.

## Licenses — FLAG
**Split license, non-commercial weights:** code is **BSD 3-Clause** (permissive, commercial-OK), but **model weights (both Pi3 and Pi3X) are CC BY-NC 4.0 — non-commercial research/education only**, stated explicitly in the repo README. This is a hard blocker for any commercial WeftOS deployment using the official checkpoints; a from-scratch retrain under BSD-only terms would be required for commercial use, or substitute a metrically-licensed alternative (e.g. DA3METRIC-LARGE, Apache-2.0) for the geometry role.

## ONNX / Rust
No official ONNX export or `candle`/`burn`/`ort` port found. Architecture (ViT-style encoder + permutation-equivariant attention + point-map/pose heads) is portable in principle but nontrivial; no evidence anyone has started this.

## Performance / Hardware
Skill-3D's own measurement (Appendix B) is the most concrete data point available: **Pi3 reconstruction takes ~21.35s on seven sampled frames** on their 4×RTX PRO 6000 Blackwell setup — by far the most expensive of the six expert tools (vs. ~0.77–1.51s for segmentation/depth/orientation). This cost is exactly why Skill-3D's learned policy shifts *away* from Pi3 toward cheaper, task-specific experts (DA3, Orient-Anything-v2) whenever possible. No official VRAM figures found. Given the latency profile, real-time use on Apple Silicon for a live glasses feed looks impractical without major optimization; offline/batch multi-view reconstruction is more realistic.

## Use in Skill-3D
Cited at §4.1 (`Wang et al. (2025c)`) as the multi-view reconstruction expert; the paper's own tool-cost analysis (Fig. 4, Appendix B) explicitly frames Pi3 as the expensive, over-relied-upon "default" tool that both GPT-5.4-without-skills and Think3D lean on too heavily, and that Skill-3D learns to use only "for layout grounding, object localization, and boundary verification" alongside cheaper tools rather than as the primary evidence source.

## WeftOS Relevance
**Verdict: SKIP (as shipped) / PATTERN (architecture).** The CC BY-NC weight license rules out direct commercial adoption, and the ~21s-per-call latency is a poor match for real-time MentraOS glasses capture regardless of license. The permutation-equivariant, no-reference-frame *architectural idea* is worth tracking as a pattern for a future honest-geometry multi-view module, but the near-term WeftOS path should prefer DA3METRIC-LARGE (Apache-2.0, faster, explicitly metric) over Pi3 for any commercial or edge-deployed geometry work.
