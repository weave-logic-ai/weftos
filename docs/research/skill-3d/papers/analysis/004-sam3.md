# [4] SAM 3: Segment Anything with Concepts

**Citation:** Carion et al. (2025). N. Carion, L. Gustafson, Y. Hu, S. Debnath, R. Hu, D. Suris, C. Ryali, K. V. Alwala, H. Khedr, A. Huang, et al. "Sam 3: segment anything with concepts." arXiv preprint arXiv:2511.16719.
**URL:** https://arxiv.org/abs/2511.16719 (code: https://github.com/facebookresearch/sam3)

## Summary
SAM 3 (Meta FAIR, Nov 2025) extends the Segment-Anything family to "Promptable Concept Segmentation": given an open-vocabulary text phrase (e.g. "yellow school bus") or visual exemplars, it detects, segments, and tracks *all instances* of that concept in an image or video, not just a single prompted object. It reports roughly double the accuracy of prior open-vocabulary segmentation systems and introduces the SA-Co benchmark plus a 4M-concept training dataset.

## Architecture / I/O
Unified detector + memory-based video tracker sharing one backbone, with a dedicated "presence head" that decouples recognition (is the concept present?) from localization (where?) to reduce confusion between the two. Input: image or video + text/exemplar prompt. Output: per-instance masks + track IDs across frames. No claim of metric geometry — this is 2D/video segmentation, not depth or pose.

## Sizes / Variants
Single flagship checkpoint released (no explicit small/base/large tiers documented like SAM2); details of parameter count not disclosed in the abstract/README as of this check — unverified beyond "backbone + presence head."

## ONNX / Rust
No official ONNX export found. `candle-transformers` ships a SAM (v1) implementation (`candle_transformers::models::segment_anything`), not SAM 3 — the concept-prompting + tracking head is new and unported. No `ort`/`burn` port found. A Rust port would need to reimplement the presence head and text-prompt grounding, non-trivial.

## Performance / Hardware
No official VRAM/latency numbers found in the abstract; Skill-3D's own measurement (§Appendix B) reports SAM3 segmentation at **~0.77s** per call in their pipeline (hardware: 4× RTX PRO 6000 Blackwell, shared across tools — not an isolated benchmark). Apple Silicon: image-only ViT-style backbones of this class typically run via PyTorch MPS or CoreML-converted ONNX, but no verified conversion path exists yet for SAM 3's tracker.

## Use in Skill-3D
Cited at §4.1 as one of six expert tools (`Carion et al. (2025)`) used for "boundary verification" and object localization; Fig. 4 notes Skill-3D "keeps moderate use of ... SAM3 ... for layout grounding, object localization, and boundary verification" rather than over-relying on it like baseline agents.

## WeftOS Relevance
**Verdict: WATCH.** Best-in-class open-vocab segmentation+tracking, but the non-OSI custom license and total absence of a Rust/ONNX path make it a Python-sidecar-only option today. For MentraOS single-camera egocentric capture, concept segmentation is useful for instance disambiguation but is not honest 3D geometry — pair with a real depth/pose expert. Re-evaluate once Meta or a third party ships ONNX weights; until then this is not adoptable inside a pure-Rust WeftOS agent without a Python subprocess boundary and explicit license review.
