# [49] RieMind: Geometry-Grounded Spatial Agent for Scene Understanding

**Citation:** Ropero et al. (2026). F. Ropero, E. Turkoz, D. Matos, J. Du, A. Ruiz, Y. Zhang, L. Liu, M. Sun, and Y. Wang. "RieMind: geometry-grounded spatial agent for scene understanding." arXiv preprint arXiv:2603.15386.
**arXiv:** https://arxiv.org/abs/2603.15386 (submitted Mar 16 2026) · Affiliation: Riemann Lab, Huawei Technologies

## Summary
RieMind is an agentic framework for static indoor 3D scene understanding that deliberately *decouples perception from reasoning*, in contrast to end-to-end VLM approaches that ingest video directly and remain coupled to implicit visual reasoning. A dedicated perception module first builds a persistent 3D scene graph (3DSG) for the scene; an LLM agent then reasons over the query by issuing structured calls to geometric tools that query the 3DSG directly — retrieving explicit locations, distances, poses, dimensions, areas, volumes, and semantic relationships — rather than inferring these implicitly from pixels. On the static split of VSI-Bench (evaluated with the 3DSG built from ground-truth annotations, giving an upper-bound-under-ideal-perception setting), RieMind substantially outperforms prior approaches.

## Method Specifics
- **Tool API shape:** structured geometric tool calls against a persistent 3D scene graph — not code/program generation. The agent queries explicit typed fields (locations, distances, poses, dimensions, areas, volumes, relationships) rather than writing executable programs.
- **Output return:** structured data — numeric/typed geometric attributes and relationship records returned directly from the 3DSG query interface back to the LLM's reasoning context (not raw images or free text).
- **Planner vs executor:** clear separation — a dedicated perception module constructs the 3DSG (executor/perception stage, run once per scene, decoupled from reasoning), and a separate LLM agent (reasoning stage) plans which geometric tools to invoke against that persistent structure to answer a query. This is the most explicit planner/perception-executor split among the six reviewed references.
- **Error handling/repair:** not specified in fetched content — no confirmed retry/self-correction loop was found; the ground-truth-3DSG evaluation setting is explicitly framed as an upper bound "under ideal perceptual conditions," implying the authors are aware perception-stage errors would propagate uncorrected in a fully automated (non-ground-truth) pipeline.

## Quantitative Results
VSI-Bench (static split): up to **16%** improvement over prior work (no task-specific fine-tuning), and **33–50%** improvement versus base VLMs. Evaluated with 3DSG built from ground-truth scene annotations, explicitly described by the authors as an upper bound under ideal perceptual conditions rather than a fully end-to-end (imperfect-perception) result.

## Metric vs Relative Geometry (important per task brief)
RieMind is explicitly **metric-first**: its scene-graph tool interface exposes real-world dimensions, distances, poses, areas, and volumes as queryable typed fields, not merely qualitative/relative spatial relations. This is the clearest "honest metric geometry" design among the six references reviewed — geometry is grounded in a persistent structured representation rather than minted from appearance-based VLM guesses. The important caveat is that the headline VSI-Bench numbers use a **ground-truth-constructed** 3DSG; RieMind's own real-world (non-oracle) perception-module accuracy — i.e. how metrically reliable the 3DSG is when built from raw sensor/video input rather than ground-truth annotations — was not found in the fetched content and needs verification before assuming the full pipeline (not just the reasoning stage) is metrically trustworthy.

## Relation to Skill-3D
Cited at §1: "Recent methods explore this paradigm by iteratively invoking tools within a per-question reasoning loop, e.g., object detection and segmentation for 2D perception, depth estimation and 3D reconstruction for geometric grounding Zhang et al. (2026c); Luo et al. (2026); Yuan et al. (2026); Ropero et al. (2026). However, these methods often fail to realize the potential of tool use in 3D reasoning and exhibit preferences toward a few dominant tools, regardless of what each scene actually requires." RieMind is one of Skill-3D's small set of directly comparable prior 3D-agentic-tool-use systems, and is implicitly critiqued by Skill-3D's claim that such per-question tool-invocation loops "fail to realize the potential of tool use ... and exhibit preferences toward a few dominant tools."

## WeftOS Relevance
**Verdict: ADOPT (as a design pattern).** RieMind's perception/reasoning decoupling — build a persistent, typed, metric scene-graph once, then let an LLM issue structured queries against it — is the closest published architecture to WeftOS's "honest geometry" principle: metric outputs come from an explicit structured representation, not minted by appearance-based reasoning. This is directly usable as a reference architecture for a WeftOS MCP tool that exposes scene-graph query primitives (distance/dimension/pose/area/volume) to Claude Code/Grok/Codex, with the important caveat that the non-oracle (real perception-module) accuracy must be independently verified before trusting metric outputs end-to-end; not directly about egocentric capture but the 3DSG-from-persistent-scene pattern is compatible with a MentraOS-fed scene-graph pipeline.
