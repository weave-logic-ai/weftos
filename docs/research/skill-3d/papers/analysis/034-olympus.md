# Ref 34: Olympus

**Citation:** Y. Lin, Y. Li, D. Chen, W. Xu, R. Clark, P. Torr. "Olympus: A Universal Task Router for Computer Vision Tasks." In Proceedings of the Computer Vision and Pattern Recognition Conference (CVPR), pp. 14235-14246, 2025. Also arXiv:2412.09612.

**Source:** arXiv:2412.09612 (https://arxiv.org/abs/2412.09612); CVPR 2025 Open Access page: openaccess.thecvf.com/content/CVPR2025/html/Lin_Olympus...; code: github.com/yuanze-lin/Olympus (CVPR 2025 Highlight)

## Summary

Olympus turns an MLLM into a universal router for over 20 computer-vision tasks spanning images, video, and 3D. A controller MLLM predicts special routing tokens (XML-like tags, e.g. `<image_gen>...</image_gen>`, `<pose_to_image>...</pose_to_image>`) that delegate sub-tasks to dedicated specialist modules (Stable Diffusion XL, ControlNet, GroundingDINO, Depth Anything V2, and others), chaining up to 5 consecutive actions to satisfy complex instructions without training any of the heavy generative specialists itself. It's trained/evaluated on two new datasets, OlympusInstruct (446.3K samples) and OlympusBench (49.6K samples).

## Method specifics

- **Tool API shape:** structured routing tokens (XML-style tags naming the task and carrying the instruction text as content) generated by the controller — not code execution, not free-form JSON, but a fixed closed vocabulary of task tags.
- **Output return path:** not fully documented in accessible sources — the paper says the framework "aggregates the results and delivers a response to the user" after specialist modules run, but the exact data structure carried back to the controller (text, image handle/URL, embedding) is not specified in the accessible abstract/HTML.
- **Planner/executor split:** yes, explicit — the controller MLLM is the planner/router; the 20 specialist models are executors. The controller also directly answers VQA-type queries itself without delegation when appropriate.
- **Error handling:** none documented — the paper reports chain-of-action capability (up to 5 tasks) but no retry, fallback, or repair mechanism for a failed specialist call or a broken chain is described.

## Results

Routing accuracy: 94.75% (single task); chained-action precision: 91.82%. Human evaluation success rate: 86.5% vs HuggingGPT's 75.2% (both using GPT-4o as controller in the comparison). Multimodal benchmark deltas over the Mipha-3B baseline: VizWiz +2.5%, MMBench +1.5%, MM-Vet +1.7%, MME Perception +31.8. Numbers found in the paper's reported results.

## WeftOS relevance

**PATTERN.** Olympus's controller-routes-to-specialist-modules design, with a closed vocabulary of task tags and explicit chaining, is a useful reference architecture for a WeftOS MCP tool router that dispatches Claude Code/Grok/Codex requests to specialized geometry/vision tools — but its outputs are general vision-task results (image generation, pose transfer, etc.), not metric geometry, and it has no documented error-repair loop, so it should inform router design rather than be adopted wholesale.
