How WeftOS runs incoming work the way Forge does: a **master controller**,
three standing loops, the WeftOS dashboard board, jobs in process-compose.

The long form (agents grep this):
[`docs/guides/agent-harness-triple-loop.md`](https://github.com/weave-logic-ai/weftos/blob/0.8-metaharness/docs/guides/agent-harness-triple-loop.md).
Decision: [ADR-098](/docs/weftos/decisions) (environment pane is **planned only**).

## Triple loop

```
                    master controller (lead)
                              │
          ┌───────────────────┼───────────────────┐
          ▼                   ▼                   ▼
   1. research loop     2. development loop   3. ops / compose
   (always on)          (plan + do ≥ 90)      (desired state)
          │                   │                   │
          └──── one board (WeftOS dashboard) ─────┘
```

| Loop | Every turn | Command |
|---|---|---|
| **Research** | Never skip | `node scripts/metaharness/crosscut.mjs` + `node scripts/dashboard-board.mjs ready` |
| **Development** | When ready exists | `node scripts/dashboard-board.mjs claim <ref>` → implement → `done` |
| **Ops** | When servers/jobs move | This repo `process-compose` on **:18090** / **:18091** |

Score is its own subtask: `scripts/metaharness/score.sh`.

The lead **routes**. Named implementers do the work. Do not wait for
Ruflo to write code. Do not start
`loop-runner.mjs --forever` unless asked.

## Add it to a repo

| Path | Role |
|---|---|
| `AGENTS.md` | Master + lanes |
| `.grok/rules/agent-harness.md` | Host rule |
| `process-compose.yaml` | Servers + `job_*` tools |
| `compose/desired.yaml` | Up/down flags |
| `compose/manifest.yaml` | Overlay admission (`overlay_ready: false` until prefixed) |
| `compose/ports.yaml` | Ports this repo claims |

Jobs are YAML processes with `disabled: true` and `mcp.type: tool`.
No ad-hoc Python for score / gate / board-ready.

The dashboard board is authoritative for WeftOS work. Its harness client uses
a host-local board credential. Imported Plane IDs remain searchable references.
Shasta, BakeOS, and Sansone keep authority over their own boards; subscribed
items appear as read-only snapshots with source links and sync timestamps.

## Why there is no machine-wide pane yet

process-compose merges like **docker-compose** (`-f a -f b`, last name
wins; paths relative to the first file). It is not terraform. Two
projects that both define `web` become one process. Two `mcp_server`
blocks share one port.

Verified on v1.120.0: merge of two files each with `web` produced **3**
processes, not 4.

Until every leaf is `overlay_ready` (unique prefix, absolute
`working_dir`, reserved PC ports), **do not** glob yamls into one
instance. See ADR-098.
